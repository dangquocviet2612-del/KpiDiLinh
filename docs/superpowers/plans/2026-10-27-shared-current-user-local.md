# Shared current-user request — local batch 8

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development / superpowers:test-driven-development. Existing Task 5 and user continuation authorize this local-only optimization. No commit, branch, reset, push or deploy.

**Goal:** Gom request `/api/me` trùng khi customers/modal/KPI cùng cần dữ liệu; không thêm khoảng cache quyền GPS và không làm sai CTV selection/report lifecycle.

**Architecture:** Một request broker chỉ giữ promise **đang chạy**, scoped theo dashboard provider và session identity id/name/role. `useCurrentUser` giữ state riêng từng consumer, cùng scope dùng chung in-flight promise; request xong xóa promise, consumer mới luôn đọc server. Không module-global user cache, TTL, localStorage, eager provider fetch hoặc server/API/auth/schema change. Hook/provider riêng không remount toàn dashboard khi session client revalidate; hide old data ngay khi scope/logout đổi. Focus/visibility-visible và online của active consumers vẫn revalidate, cùng event được coalesce. Explicit retry được hỗ trợ, không auto-retry loop. API hiện có 30s cache vẫn tồn tại, không gọi đây là thu hồi JWT/quyền tức thì.

**Choice:** (1) In-flight-only sharing được chọn: ít thay đổi correctness, không tiết kiệm request giữa các lần mở modal tuần tự. (2) Thêm client TTL bị loại vì chồng staleness lên server cache quyền. (3) Gộp modal `/api/users` vào me.ctvList bị loại vì chưa tương đương contract. Không đổi UI/flow nghiệp vụ.

**Guardrails:** Primary đang có 12 thay đổi batch 6–7; snapshot 386 file, 314 source file khớp checkout. Primary HEAD `9d0365e`, worktree detached `1ecfa38`; không reset checkout cũ. Chỉ fake SQLite đã quản lý và localhost3006, không env/credentials/database thật/Turso/Vercel. Không sửa nguyên nhân `/api/me` 500 từng thấy trên production.

## Files and responsibilities

- New `src/lib/current-user-request.ts`: current-user response/error types; instance-scoped cancellable request broker. A consumer abort/unmount không hủy request consumer khác; last-consumer abort hủy và bỏ pending entry, late success/error không refill. Dispose old scope cancels old request; same-scope object/expiry refresh không tạo request mới. Non-2xx/JSON/network failure không cached; next mount/retry làm request mới. Never return mutable Response body to multiple consumers: parse JSON once.
- New `src/hooks/useCurrentUser.tsx`: provider owns isolated broker per stable authenticated scope, no eager fetch; hook exposes data/error/loading/refresh. Each consumer maintains its own subscription/abort, ignores stale results on scope/unmount; clear/mask data synchronously on new scope/logout. Initial loading without session and unauthenticated must not fetch. Real SessionProvider.update() loading with retained authenticated data must preserve broker/subscription/data and not fetch again; add real-provider regression. Successful payload must have the expected user id; reject subject-B payload while session still says A. Entry identity/epoch fences prevent obsolete completion/cleanup clearing a replacement. Missing provider may use hook-local isolated broker, never global sharing.

## Acceptance / limitations

- At most one in-flight GET me per active scope; removing one caller does not break another. New consumer after settlement deliberately creates a new GET (no resolved permission cache).
- No previous subject/role data usable during scope transition or after logout, including A→B→A pending races and late responses that ignore abort. Same identity/expiry refresh preserves report/draft and does not fetch me unless explicit focus/online/refresh event.
- Active consumers can recheck server on visibility/online/retry. HTTP 401/403/404/500 and network/parse errors do not become a successful cached result or enable GPS. Existing API auth and server cache remain authoritative/unchanged.
- All prior batch 6–7 source changes preserved. This does not close JWT/version/multi-instance/in-flight server cache gaps or all roadmap tasks.
